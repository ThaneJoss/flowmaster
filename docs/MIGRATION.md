# 兼容与迁移说明

本轮更新调整产品流程、客户端状态管理和服务内部结构。对外继续使用 `/mcp`，项目、流程、步骤、记录、资料的已有 ID 和 Token 保留。数据库沿用现有 D1 表与迁移，不要求删除数据、重建数据库或重新签发 Token。

## 界面名称与工具名称

| 新界面名称 | 保留的数据 / 工具名称 |
| --- | --- |
| 项目 | `projects` |
| 流程 | `hypotheses` |
| 步骤 | 流程内 `nodes`；专用 `nodes_*` 工具 |
| 执行记录 | `experiments`；录入使用 `results_create` |
| 资料 | `resources` |

研究内容不会因为界面名称调整而转换成另一种数据。顶层“项目 / 连接与设置”替代原来六个平级入口，项目内的“流程 / 记录 / 资料”共享明确的项目上下文。

新链接形如 `#projects/<projectId>/flows?flow=<id>&step=<id>`，切换项目子页保留已选流程 / 步骤。旧 `#workspace`、`#experiments`、`#resources` 在仅有一个项目时进入对应子页，多项目时先显示项目列表；旧 `#mcp`、`#api` 打开设置中的接入说明。

## 当前结果与旧节点

执行记录是结果的事实来源，步骤可通过 `currentResultId` 指定当前真实结果。新建真实记录会成为该步骤的当前结果；修正当前记录同步修改步骤的兼容结果字段；删除当前记录清空关联及派生结果，不自动选择另一条历史记录。

没有 `currentResultId` 的旧节点保留已有结果内容，以“历史摘要”方式显示，不凭空生成执行记录。旧数据中“未出现该字段”与新数据显式 `currentResultId: null` 的语义不同；前者是未建立关联的旧结果，后者是用户已明确清空当前结果。旧步骤缺少 `progress` 时显示未设置，不从结果状态推断进度；新步骤的进度初始为 `pending`。

旧 `source: "agent"` 记录继续可读，并标记为历史模型建议。新版本不会再次调用模型，也不允许新建冒充的模型执行记录或将模型建议选为真实当前结果。既有记录的来源和所属关系不能通过编辑改写。

## 时间与历史

新增 `recordedAt` 标记录入时间。旧记录缺少有效值时，读取时从首个有效 ISO 日期日志时间或旧 `updatedAt` 推断，并附带 `recordedAtInferred: true`。界面标记历史时间推断，不能理解为准确恢复了原始实验时间；修正保留录入时间和推断标记。

`updatedAt` 继续表示最近修订时间，步骤 `startedAt` 保留实际开始时间，录入结果不自动覆盖它。实际耗时由记录提供。

删除步骤保留执行记录，记录中的步骤标题快照用于说明原归属；记录页仍可查看和修正这类历史。已不存在的步骤不能再被定位或设定当前结果。删除整个流程仍有级联删除记录的影响，操作前应核对确认说明。

## 资料关联

步骤和记录使用 `resourceIds` 引用所属项目资料。旧数据缺少该字段时按无引用兼容。资料被引用后，不能直接删除或改到其他项目；应先解除引用，再完成操作。

## MCP 客户端兼容

现有集合 CRUD 工具及 `results_create` 保留。客户端应从 `tools/list` 获取当前输入 schema。结果创建 / 修订 / 删除在原 `data` 返回值之外增加 `affectedHypothesis`，可用它更新本地流程缓存；旧客户端仍能读取原 `data`。

新步骤工具处理新增、局部编辑、移动、布局、删除和当前结果选择，避免为一个步骤的位置变化替换整份流程。工具仍要求流程 revision。集合更新现在支持待更新字段与 `revision`，也兼容完整记录。`hypotheses_update` 无需携带整张图即可修改流程元信息；整份更新仍需遵守当前结果和资源关联约束。

列表仍返回 `{data, total}`，实验列表增加项目、流程、步骤和状态筛选。旧 `workspace_get` 保留快照上限；新浏览器按项目加载、历史分页，导出显式遍历所需列表，不再把本地缓存当完整工作区。

原 REST `/api`、`/api/*` 和 `/openapi.json` 仍返回 404，没有重新开放。`ENCRYPTION_KEY`、`MODEL_ALLOWED_HOSTS` 不再需要；历史模型设置行不会自动删除，也不会被读取用于模型请求。管理员可按自己的凭据保留策略处理旧配置。

## 升级注意事项

部署前保留现有 D1 绑定与 `ADMIN_TOKEN`，无需新增数据库迁移。外部客户端若使用完整记录替换，应先读取最新 revision；推荐只提交变化字段或改用专用步骤工具，减少整份替换。不要把 409 冲突作为可无条件重试的写入错误。合并后的单条文档有 600,000 UTF-8 字节上限，小补丁也可能因为整条记录超限而返回 413；既有数据不会因此被自动删除。

## 手动验收清单（未执行）

以下供人工验收使用，只记录清单，不表示已经执行。执行状态见 [VALIDATION.json](VALIDATION.json)。

- [ ] 新建项目和流程后直接进入；切换流程 / 记录 / 资料时，项目范围持续可见。
- [ ] 步骤移动、布局与保存只更新相关内容；草稿、冲突提示、切换项目的迟到请求处理正确。
- [ ] 新建 / 修正 / 删除当前记录后，步骤结果一致；非当前记录修订不覆盖当前结果，显式切换结果有效。
- [ ] 旧节点摘要、显式空当前结果、历史 agent 建议有区分；旧记录时间推断不会冒充准确实验时间。
- [ ] 录入结果不覆盖 startedAt，修订不重置 recordedAt；删除步骤后历史仍可看、可修正，删除流程明确级联影响。
- [ ] 资料只能在项目内引用；已引用资料删除 / 换项目受阻，解除引用后可操作。
- [ ] 项目记录与步骤历史分别筛选 / 分页；完整导出覆盖全部匹配页，工作区导出覆盖四集合，不只导缓存。
- [ ] read / write / admin 权限、撤销、过期、Origin 和 revision 校验生效；退出 / 换账号不展示旧数据。
- [ ] 已有 MCP CRUD 客户端仍读取 data，新客户端合并 affectedHypothesis；旧 REST 和模型调用没有重新开放。
