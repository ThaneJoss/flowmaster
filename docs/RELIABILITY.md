# 可靠性审查

以下结论来自代码审查与本地验证。生产打包通过不代表 Cloudflare 远端部署通过；本地未读取到失败构建的错误日志，不能据此认定远端失败原因。

## 本次已修正

- **主分支漏检**：GitHub Actions 的 push 触发器此前只监听旧开发分支，现已加入 `main`。
- **工具链声明不完整**：增加 `.node-version`，让本地、GitHub 和支持该文件的构建环境使用 Node 24；CI 读取同一文件。pnpm 仍固定为 11.25.0。
- **部署验证边界不清**：增加 `deploy:doctor`，本地配置与远端预览默认绑定分开检查。未配置凭证或未验证的事项不会被报告为远端部署成功。
- **预览配置与迁移说明不完整**：明确预览 DB、Secret 和迁移配置的独立性，并给出显式选择迁移目标的示例。详见 [部署排查](DEPLOYMENT.md)。

本地使用 pnpm 11.25.0 进行了全新 `--frozen-lockfile` 安装，保留全部依赖安装安全校验；安装、类型检查、Vite 构建、静态资源校验与 Worker 生产 dry-run 均通过。只读诊断的成功、缺失绑定和权限错误分支使用本地模拟响应验证，未调用真实远端 API。

## 仍需修复的业务风险

### 全量快照上限与网页入口不兼容

[service.ts](../lib/server/service.ts) 的 `snapshot()` 在文档数据超过 8,000,000 字节或 5,000 条时返回 `WORKSPACE_TOO_LARGE`。[App.vue](../web/src/App.vue) 的登录必须先成功读取整个快照，每次写入后也强制重新读取快照。

后果：已有工作区达到上限后，网页无法登录。新增记录跨过上限时，服务端写入已经成功，但随后的刷新报错，表单仍保留；用户重试可能重复创建记录。刷新失败不能等同于写入失败。

建议：将网页登录和浏览改为分页读取；写入响应作为提交成功的依据，刷新失败单独提示。该问题尚未在此次部署配置修复中改变。

### 分页缺少响应体字节预算

服务端允许单个文档约 600 KB，列表一次最多读取 200 条完整记录，理论原始数据约 120 MB。[mcp.ts](../lib/server/mcp.ts) 又同时创建文本 JSON 与结构化结果，这会进一步增加内存占用。

后果：按条数分页仍可能超过 Worker 内存或 D1 响应限制，不能保证大记录场景可用。这是静态边界分析，尚未进行生产压测。

建议：按响应体字节预算分页，并提供明确的下一页位置；同时检查客户端的分页结束条件，避免把短页错误当成全部读完。该风险尚未在此次部署配置修复中改变。
