## 工作区分页与保存反馈

旧实现的网页登录和写入后刷新依赖整个工作区快照，超过 8,000,000 字节或 5,000 条记录后会报 `WORKSPACE_TOO_LARGE`。当前网页改为按页面、项目和节点加载列表，提供继续加载、搜索和失败重试；快照工具保留原限制供外部客户端兼容使用。浏览器将可见列表与已读记录缓存分开，切换分页不会被误判为删除假设而清除节点草稿。

写入成功后，页面立即接收响应中的记录、版本号和关联假设，关闭已提交表单。后续列表刷新失败单独提示并提供刷新按钮；刷新重试不会再次提交创建请求。Token 创建也会先显示仅返回一次的明文，再刷新列表。

列表工具同时限制记录数量和 UTF-8 JSON 字节数。D1 先用记录大小和元数据选出连续的记录前缀，再将有界的正文返回 Worker；实验列表只投影所需节点标题，不读取完整父假设。服务端再检查补齐历史字段后的序列化大小，单页结构化结果控制在 1,000,000 字节以内。MCP 的文本结果和协议封装会增加实际传输字节数。

列表返回 `nextOffset`，短页也可能还有后续数据。网页和显式导出都依据此字段继续读取；超过支持大小的历史单条记录报错，不会静默跳过。完整导出只在用户点击时逐页读取，不增加网页登录和日常浏览的开销。

### 验证边界

分页使用 offset，不保证其他客户端同时增删记录时仍是固定时点快照；需要一致备份时应使用数据库备份。已浏览记录和导出文件仍占用浏览器内存，超大数据量下的长期内存、深分页速度和生产负载仍需实际测量。本地测试不能代替线上部署验证，具体已执行检查见 [验证记录](VALIDATION.json)。
